# 企业账号的月度额度

规范：[enterprise-spend-control](../openspec/specs/enterprise-spend-control/spec.md)。

`ent26` 等账号可能不返回 5 小时或每周额度，而是在
`spend_control.individual_limit` 返回支出预算。支持由响应内容决定，
不依赖固定套餐名或固定的 $200 上限。

ent26 的账号列表、仪表盘卡片和账号详情统一展示月度剩余百分比和上游重置时间，
使用与每周额度相同的进度条和重置提示，不再单独显示“支出额度”面板或上限/已用明细。
百分比来自上游；仅在上游缺失百分比时，按其已用比例或余额/上限计算。
不使用请求日志费用推算，也不把美元换算为订阅 credits。

仪表盘卡片和账户表格原有的“订阅额度”位置显示 ent26 当前剩余的 USD 金额，
例如 `$116.67`，保留美元符号和两位小数。仅使用上游的真实余额，不从百分比反推。
金额缺失、无效或单位不是 USD 时显示未知；0 显示 `$0.00`，负余额保留负号。
USD 不进入订阅 credits 汇总或路由分数，表格按单位分组后在同单位内排序。

没有订阅窗口的账号不显示虚构的 5h/每周额度。有预算又有真实订阅窗口时，
真实窗口与月度比例均保留。未知值显示未知，不默认 0 或 100%。
月度标签是 ent26 的展示语义，不会伪造 30 天窗口、月初重置时间或 usage_history。

预算通过独立表按本地账号保存，同一工作区不同成员互不覆盖。
查询失败保留旧值及原更新时间。明确收到空控制才清除；较旧的并发响应
不能覆盖较新的记录。

“自定义权重 × 剩余额度”按每个账户最低剩余比例的平方乘以自定义权重，
在所有可用账户之间按概率随机抽取；不再使用套餐/账号优先级或低额度降级规则。
Compass Model Source 暂用 100% 占位，不代表上游真实余额。
预算耗尽时不再分配新请求；存在 credits 不会绕过预算限制。只有上游确认
恢复可用后才恢复分配，不根据本地时间自动假设预算已经重置。

最初的额度获取功能使用迁移 `20261028_000000_add_provider_spend_controls`；
本次展示和路由调整无需新迁移。原始快照及 spendControl API 字段保留兼容。
源码验证不会自动重启生产服务或切换前端，启用仍需管理员安排发布。
无需重新登录、重置 API Key 或修改历史账单。
