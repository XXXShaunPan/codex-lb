# 企业账号的支出额度

规范：[enterprise-spend-control](../openspec/specs/enterprise-spend-control/spec.md)。

`ent26` 等账号可能不返回 5 小时或每周额度，而是在
`spend_control.individual_limit` 返回支出预算。支持由响应内容决定，
不依赖固定套餐名或固定的 $200 上限。

账号列表、仪表盘卡片和账号详情会展示预算单位、上限、已用、剩余金额、
剩余比例、上游重置时间和最近获取时间。金额来自上游，不是 Codex-LB
请求日志费用的累加；美元也不会换算成订阅 credits。

没有订阅窗口的账号不显示虚构的 5h/每周额度。有预算又有真实订阅窗口时，
两种额度均保留。未知值显示未知，不默认 0 或 100%。

预算通过独立表按本地账号保存，同一工作区不同成员互不覆盖。
查询失败保留旧值及原更新时间。明确收到空控制才清除；较旧的并发响应
不能覆盖较新的记录。

加权路由会使用预算剩余比例，并继续遵守原有的权重、优先级及低额度规则。
预算耗尽时不再分配新请求；存在 credits 不会绕过预算限制。只有上游确认
恢复可用后才恢复分配，不根据本地时间自动假设预算已经重置。

本地实现包含迁移 `20261028_000000_add_provider_spend_controls`。上线前先备份
数据库，执行迁移并重启后端，再发布前端资源。无需重新登录、重置 API Key
或修改历史账单。
